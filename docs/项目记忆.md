# DH.NStardust 的 .NET 11 接入（2026-09-14）

## 落地范围（已改）
- 库/多目标工程 `TargetFrameworks` 末尾追加 `net11.0`：
  `DH.NStardust`（`...;net10.0;net10.0-windows;net11.0`）、`DH.NStardust.Extensions`、`StarAgent`、`Plugins/AgentExpansion`、`DeployAgent`（`net8.0;net10.0;net11.0`）
- 三个 workflow（`publish.yml` / `publish-beta.yml` / `test.yml`）setup-dotnet 列表追加 `11.x`（原为 6.x~10.x）
- `global.json` 无需改：`9.0.102 + rollForward latestMajor + allowPrerelease true` 即可解析到 SDK 11.0.100-rc.1

## 刻意未加 net11.0-windows
- 现有 windows TFM 写法是给每个 TFM 挂 `FrameworkReference Microsoft.WindowsDesktop.App.WindowsForms TargetingPackVersion="X.0.0"`（精确版本，便于在非 Windows 主机上经 NuGet 拉取）
- 但 11.0 的目标包目前只有 SDK 自带 `11.0.0-rc.1.26425.128`，nuget.org 上无 `Microsoft.WindowsDesktop.App.Ref 11.0.0` → 若照抄 `TargetingPackVersion="11.0.0"` 会还原失败
- 如需 `net11.0-windows`：要么省略 `TargetingPackVersion`（用 SDK 自带包），要么等 .NET 11 正式版再补

## 未覆盖的工程（均为有意）
- 单目标 `net10.0` 的应用/测试（Stardust.Server、Stardust.Web、StarGateway、Test、Samples/TestA~C、ClientTest、ServerTests、Stardust.Tests、Stardust.McpClientTests）：按 DH.NCode 参考做法保持不动
- `Stardust.Data`（netstandard2.1）、`Plugins/MySqlAgent`、`Plugins/NetworkDetect`（net45;netstandard2.0）：netstandard 资产本身即可被 net11 消费
- `Installer`（net40~net7.0，已过时）、`StarAgentTool`（net6.0）：均不在 `DH.NStardust.slnx` 中，未处理

## 若要给应用也加 net11.0 需注意
- `Stardust.Server`、`Stardust.Web`、`StarGateway`、`Test`、`Samples/TestA~C` 设了 `<AppendTargetFrameworkToOutputPath>false</AppendTargetFrameworkToOutputPath>`，多目标会把两个 TFM 输出到同一目录互相覆盖，需先改成按 TFM 分目录（如 `..\Bin\Web\$(TargetFramework)`）或保持单目标
